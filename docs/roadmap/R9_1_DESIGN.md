# R9.1 Design — ComfyUI contracts, local endpoint boundary and capability schema

## Status

Implementation candidate on `r9/1-comfy-contracts`. R9.1 has **manual intervention: NONE**.

## Purpose

R9.1 establishes the transport-independent contracts for the R9 ComfyUI integration. It deliberately performs no HTTP, WebSocket, filesystem discovery, model resolution, workflow execution, output retrieval, process launch or GPU action. Those capabilities remain blocked until their planned subdivisions.

## Frozen security decisions

### Explicit loopback literal only

`ComfyEndpoint` accepts only explicit `127.0.0.1` or `::1` origins with an explicit port. `localhost`, wildcard listeners, LAN/private addresses and public addresses are rejected without DNS resolution.

This is intentionally stricter than accepting a hostname whose current resolution happens to be loopback: endpoint acceptance must not depend on mutable DNS/hosts-file state. ComfyUI may itself be configured to listen on wider interfaces, but Kodepoia R9 does not treat such listeners as trusted endpoints.

Accepted schemes are `http` and `https`. The endpoint object derives the matching `ws`/`wss` origin for later R9.2 use but opens no connection.

Credentials, non-root origin paths, queries and fragments are rejected. Redirect locations may contain a route only when the resulting URL retains the exact accepted scheme, literal host and port.

### No generic transport surface

R9.1 introduces no generic request method, socket API, subprocess API, arbitrary route, host, HTTP method or workflow graph execution entry point. R9.2 will add a fixed typed client on top of this boundary.

### Explicit states

R9.1 defines capability, queue, run and resource states. Run transitions fail closed: a PREPARED run cannot jump directly to SUCCEEDED, and terminal states cannot return to active states. `UNKNOWN` remains explicit so later crash/history reconciliation can recover from missing local knowledge without fabricating a success state.

### Inert server references

Prompt/history/output references are immutable bounded evidence only. A ComfyUI filename or subfolder is not a Kodepoia filesystem path and is never asset identity. R9.6 must validate/retrieve such references through the accepted client and R8 boundaries before any generated byte can be promoted.

### Deterministic serialization

R9 canonical JSON uses UTF-8, sorted keys, compact separators and rejects NaN/Infinity. SHA-256 evidence is computed over those canonical bytes. Versioned envelopes contain exactly `schema`, `version` and `payload`; mismatched schemas or unsupported versions fail closed.

## Versioned schema roots

R9.1 adds these Draft 2020-12 roots:

- `comfy-capability-snapshot-v1.schema.json` → `kodepoia.comfy-capability-snapshot`;
- `comfy-workflow-definition-v1.schema.json` → `kodepoia.comfy-workflow-definition`;
- `comfy-run-manifest-v1.schema.json` → `kodepoia.comfy-run-manifest`;
- `comfy-vram-evidence-v1.schema.json` → `kodepoia.comfy-vram-evidence`.

The root envelope is strict now. Payload members are intentionally not frozen in R9.1: R9.3, R9.4, R9.5 and R9.8 respectively own the detailed payload contracts and will tighten them without creating a second root-envelope convention.

## Transport budgets

`ComfyTransportLimits` freezes bounded defaults before R9.2 exists:

- connect timeout: 5 s;
- read timeout: 30 s;
- total operation timeout: 120 s;
- JSON response maximum: 8 MiB;
- binary response maximum: 256 MiB;
- WebSocket frame maximum: 16 MiB.

All timeout values must be positive and finite; all byte limits must be positive integers. These are R9 client safety defaults, not claims about ComfyUI server-side upload or execution limits.

## External compatibility observations used during design

Current ComfyUI material reviewed during R9 planning/implementation continues to expose the traditional prompt/queue/history/object-info/system-statistics/WebSocket surface, while newer API material also contains job-oriented endpoints. ComfyUI startup documentation retains `127.0.0.1` as the default listen address and documents that `--listen` without a value broadens listening to all IPv4/IPv6 interfaces.

These observations are compatibility input only. They do not expand Kodepoia's accepted endpoint boundary and do not make an upstream route authoritative until R9.2 models it as a fixed typed operation.

## Test strategy

`tests/test_comfyui_r9_1.py` covers:

- IPv4/IPv6 loopback normalization and HTTP→WebSocket scheme derivation;
- remote/LAN/wildcard/hostname/credential/path/query/fragment/missing-port rejection;
- same-origin redirect acceptance and cross-origin redirect rejection;
- deterministic canonical JSON/SHA-256 and NaN rejection;
- strict versioned envelope loading;
- run-state transition rules;
- bounded inert prompt/history/output references;
- finite positive transport limits;
- validation and root-tamper rejection for all four JSON schemas;
- an offline invariant that monkeypatches DNS lookup, socket construction and subprocess creation to fail if R9.1 touches them.

## R1–R8 compatibility

R9.1 adds no new external process boundary and does not weaken `WorkspaceBoundary`, `VaultBoundary`, Guardian/PermissionSet, KillSwitch, Secrets, R6 governance, R7 ResearchGuard or R8 Asset/Vault identity. It therefore requires no ADR.
