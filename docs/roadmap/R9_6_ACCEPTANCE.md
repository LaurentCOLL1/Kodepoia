## Accepted behavior

R9.6 promotes only explicit output references from an already reconciled R9.5 `SUCCEEDED` run. Every requested output is retrieved through the fixed loopback `ComfyUIClient`, validated for reference/path policy, byte size, SHA-256 and supported image signature/extension, staged under the governed project boundary, and reverified before any media promotion occurs.

The bridge deliberately reuses the frozen R8 authorities rather than creating a parallel asset stack:

- canonical generation evidence is ingested through R8 `AssetService` as a Vault-local DOCUMENT source revision;
- generated media is promoted as R8 `DERIVED` revisions by the unchanged R8 `TransformService`;
- lineage inputs include that exact generation-evidence revision and any explicitly supplied source revisions;
- the transform recipe binds run/workflow/model/capability/instance/prompt/settings/seed/output-reference/content evidence;
- R8 conservative governance remains authoritative, so absent legal evidence remains unknown/`NOASSERTION` rather than fabricated exportability.

## Multi-output failure rule

The full declared retrieval/validation set is preflighted before the first R8 promotion. A rare failure after promotion has begun cannot be represented as complete: R9.6 persists explicit `PARTIAL` evidence naming only revisions that actually exist and raises `ComfyPartialCaptureError`. It performs no hidden destructive rollback around R8 deletion/reference policy.
